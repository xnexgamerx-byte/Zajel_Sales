# خطة تحويل زاجل CRM إلى نظام متعدد المستخدمين

## الهدف
تحويل النسخة الحالية (ملف HTML واحد، البيانات في متصفح كل مستخدم) إلى نظام مشترك للموظفين،
**مع الحفاظ على التصميم والشاشات كما هي بدون أي تغيير**، وبواجهة API نظيفة لربطه لاحقاً بنظام الشركات الأخرى.

## المبدأ
- `original/zajel-original.html` = النسخة الأصلية، لا تُعدَّل أبداً.
- `scripts/build.mjs` = يطبّق تعديلات محددة ومحدودة على الأصلية وينتج `public/index.html`.
  أي تعديل على الواجهة يظهر كسطر واضح في هذا الملف (قابل للمراجعة).
- `src/worker.js` = السيرفر (Cloudflare Worker): تسجيل الدخول، المزامنة، الملفات، API للربط.
- Cloudflare D1 = قاعدة البيانات، R2 = الملفات.

## المراحل
1. ✅ **الأساس**: دخول حقيقي، بيانات مشتركة بين الأجهزة، مزامنة شبه لحظية، رفع الملفات، API للربط.
3. **مكتبة المعرفة (Zajel Knowledge)**: نقل حالتها وملفات PDF من IndexedDB إلى السيرفر.
2. ✅ **صلاحيات على مستوى السيرفر**: فرض صلاحيات كل موظف (views/actions) داخل الـ API وليس في الواجهة فقط.
4. **الربط مع نظام الشركات**: مفاتيح API لكل شركة، Webhooks، تصدير/استيراد.

## ملاحظة عن تعدد الشركات
كل شركة = نسخة مستقلة (Worker + D1 + R2 خاصة بها). هذا أبسط وأكثر عزلاً من قاعدة واحدة مشتركة.
