# زاجل CRM — نسخة الفريق

نفس تصميم وشاشات النسخة الأصلية بدون أي تغيير، لكن البيانات الآن على **سيرفر مشترك** بدل متصفح كل مستخدم.

## الهيكل
| المسار | الوظيفة |
|---|---|
| `original/zajel-original.html` | النسخة الأصلية. **لا تُعدَّل أبداً** |
| `scripts/build.mjs` | تعديلات محددة على الأصلية → `public/index.html` (كل تعديل واضح ومراجَع) |
| `src/client/zajel-sync.js` | طبقة المزامنة في المتصفح |
| `src/worker.js` | السيرفر: دخول، مزامنة، ملفات، API للربط |
| `migrations/` | جداول قاعدة البيانات (D1) |
| `PROJECT_BRIEF.md` | ملخص المشروع الوظيفي والقرارات (من صاحب المشروع) |
| `docs/API.md` | توثيق الـ API للربط مع نظام الشركات |
| `src/knowledge.js` | مكتبة المعرفة على الخادم (سجلات + نص الصفحات + PDF الأصلي) |
| `src/client/kn-store.js` | تخزين المكتبة في المتصفح على الخادم بدل IndexedDB |
| `src/phones.js` | توحيد أرقام الهواتف العراقية وكشف التكرار |
| `src/permissions.js` | قواعد الصلاحيات على السيرفر |
| `test/permissions.test.mjs` | اختبارات قواعد الصلاحيات |
| `test/e2e.cjs` | متصفحات حقيقية: مدير + موظفتان، مشاركة البيانات ومحاولات التجاوز |

| `test/password.cjs` | تغيير كلمة المرور من النافذة |

| `test/screens.cjs` | فتح الشاشات الـ24 والتأكد من عدم وجود أخطاء JavaScript |

## التشغيل محلياً
```bash
npm install
npm run db:init
npm run dev          # http://localhost:8787  (المدير: manager / كلمة المرور من .dev.vars)
npm test             # يحتاج السيرفر شغال
```

## النشر على Cloudflare (مرة واحدة)
```bash
npx wrangler login
npx wrangler d1 create zajel            # انسخ database_id إلى wrangler.jsonc
npx wrangler r2 bucket create zajel-files
npm run db:init:remote
npx wrangler secret put SESSION_SECRET   # نص عشوائي طويل (32+ حرف)
npx wrangler secret put ADMIN_PASSWORD   # كلمة مرور حساب manager الأول
npx wrangler secret put INTEGRATION_API_KEY   # مفتاح ربط النظام الخارجي (اختياري)
npm run deploy
```
بعد أول دخول للمدير تُنشر القوالب والمحتوى الأساسي للجميع (بدون العملاء التجريبيين). كل شركة جديدة = نشر منفصل بقاعدتها وملفاتها.

## ما تغيّر عن الأصل (ملخص)
- الحفظ: من `localStorage` إلى السيرفر، مع مزامنة كل ~8 ثوانٍ، وكل عنصر (عميل/مهمة/…) يُحفظ لوحده فلا يطغى تعديل موظف على آخر.
- الدخول: حقيقي (كلمات المرور مشفّرة PBKDF2 على السيرفر، جلسة HttpOnly)، والجلسة تبقى بعد تحديث الصفحة.
- الملفات المرفوعة (المكتبة/التسجيلات): في R2 بدل IndexedDB.
- حُذفت ملاحظات "نسخة تجريبية/هذا المتصفح" لأنها صارت غير صحيحة، وكُتب تحذير على زر حذف/استبدال البيانات.

## الصلاحيات (مفروضة من السيرفر)
المدير يحدد لكل موظف الشاشات والإجراءات من «الفريق والصلاحيات» كالسابق، والسيرفر يطبقها فعلياً (`src/permissions.js`):
- **القراءة:** الموظف بدون «الاطلاع على جميع التجار» يستلم تجاره فقط ومتابعاتهم وأنشطتهم وعروضهم. التاجر المُعاد إسناده يختفي عنده ويظهر عند الموظف الجديد. بيانات الشاشات غير المسموحة (التدقيق، التسويق، عروض الأسعار…) لا تُرسل له.
- **الكتابة:** تغيير المرحلة ← `changeStage`، تغيير المسؤول ← `assign`، اعتماد العروض/الحملات ← `quotesApprove`/`campaignApprove`، القوالب والمكتبة والتسويق والإعدادات كلٌّ بصلاحيته. لا أحد غير المدير يعدّل الفريق أو ينشئ حسابات.
- **تكرار التاجر:** السيرفر يرفض أي رقم هاتف مسجل لتاجر آخر، حتى لو كان عند موظف لا يراه، وبأي صيغة (`0770…` أو `+964 770…` أو أرقام عربية)، ويذكر اسم التاجر والموظف المسؤول.
- **سجل التدقيق:** إضافة فقط؛ لا يُعدَّل ولا يُحذف إلا من المدير.
- التعديل المرفوض يعود لقيمته على السيرفر مع رسالة توضح السبب، ولا يوقف باقي التعديلات.

## تغيير كلمة المرور
كل مستخدم يغيّر كلمته بنفسه بالضغط على بطاقة اسمه في الشريط العلوي (الحالية + الجديدة مرتين، 8 أحرف على الأقل). المدير يعيّن كلمة جديدة لموظف من «الفريق والصلاحيات». ملاحظة: تغيير كلمة المرور لا يُنهي الجلسات المفتوحة على أجهزة أخرى فوراً (تنتهي بعد 14 يوماً أو بتعطيل الحساب).

## مكتبة المعرفة المشتركة
- الكتب والأفكار والمسودات والحقائق المعتمدة محفوظة على الخادم ومشتركة بين الموظفين. المعالجة (PDF.js وOCR والقواعد) ما زالت في متصفح من يرفع الملف، بدون أي ذكاء اصطناعي أو API مدفوع.
- نص الكتاب يُحمَّل عند الحاجة فقط (معاينة، تحليل، OCR)، ويُحفظ على شكل مقاطع من 50 صفحة؛ OCR لنطاق صغير يرفع مقطعاً واحداً.
- الصلاحيات (كانت كل عمليات المكتبة للمدير فقط رغم وجود الخيارات في شاشة الفريق):
  - **تشغيل مكتبة المعرفة الذكية**: رفع وتحليل وOCR وتعديل المسودات.
  - **اعتماد رسائل المعرفة**: اعتماد/رفض المسودات فقط.
  - **المدير**: حذف الكتب، الحقائق المعتمدة، التصدير والاستعادة.
  - شاشة «مكتبة المعرفة» ضمن صلاحيات العرض شرط لقراءة المكتبة أصلاً.

## محدوديات معروفة (المراحل القادمة)
1. **مكتبة المعرفة:** تحديثات الزملاء تظهر عند فتح الشاشة أو بعد 15 ثانية من آخر تحميل (ليست لحظية مثل التجار). ملف PDF الأصلي يُحفظ على الخادم حتى 100 ميغابايت (حد Cloudflare للطلب)؛ الأكبر يُقبل ويُقرأ نصه، لكن OCR للصفحات اللاحقة يتطلب إعادة اختيار الملف.
2. التعديل المتزامن لنفس العنصر: آخر حفظ يفوز (تعديل عناصر مختلفة لا يتعارض).
3. الملفات المرفوعة تُنزَّل لأي مستخدم مسجّل يعرف معرّفها (معرّف عشوائي 128-bit).
4. بقيت عبارات "تجريبي" في رسائل ثانوية (مثل حد استيراد 500 سطر ورسائل في مكتبة المعرفة).

## نشر تجريبي بدون حساب
`wrangler deploy --temporary` ينشر على حساب Cloudflare مؤقت (يُحذف إن لم تستلمه عبر رابط claim خلال ساعة تقريباً). الحساب المؤقت لا يدعم R2، فعند غيابه يعمل كل شيء عدا رفع الملفات ومكتبة المعرفة (يعطيان رسالة واضحة). النشر الحقيقي على حسابك يستخدم `wrangler.jsonc` مع R2 كما في الخطوات أعلاه (تفعيل R2 قد يتطلب إضافة بطاقة دفع في Cloudflare حتى لو ضمن الحد المجاني).
